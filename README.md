## Overview

All of these run Apache NiFi 2.12.0. NiFi 2.x only serves HTTPS, so unless noted otherwise log in at `https://localhost:8443/nifi` with username `root` and password `rootrootroot` (accept the self-signed certificate warning).

* docker-compose-cluster.yml - Secure 3 node NiFi cluster (ports 8443-8445). NiFi 2.x has no embedded ZooKeeper, so a standalone ZooKeeper is still required.
* docker-compose-arangodb.yml - ArangoDB.
* docker-compose-nifi-with-cockroachdb.yml - 3 node CockroachDB cluster
* docker-compose-elasticsearch.yml - ElasticSearch.
* docker-compose-postgres.yml - PostgreSQL.
* docker-compose-sentinel.yml - Redis master, replica and sentinel (master name `mymaster`).
* docker-compose-solrcloud.yml - Two node SolrCloud cluster w/ ZooKeeper.
* docker-compose-ignite.yml - Apache Ignite support.
* docker-compose-mongo-ssl-shard.yml - MongoDB with SSL authentication and sharding.
* docker-compose-mongo-ssl.yml - MongoDB with SSL and simple replication.
* docker-compose-registry-secure.yml - A secure NiFi Registry example with LDAP login (users `admin` and `test`, password `secret`).
* docker-compose-registry-simple.yml -A simple NiFi Registry example without security enabled.
* docker-compose-janusgraph.yml - A configuration that connects NiFi with JanusGraph.
* docker-compose-integration-test.yml - LDAP secured NiFi plus Elasticsearch, Kibana, MongoDB and PostgreSQL.

## Secure Samples

`docker-compose-registry-secure.yml` and `docker-compose-integration-test.yml` use PKCS12 stores generated by `generate_registry_certs.sh` (password `registrydemostorepass`). Log in with an LDAP user such as `admin` / `secret`.

## Mongo Shared Configuration for SSL

The certificates in `nifi_mongo` are demo material generated by `generate_mongo_certs.sh` (valid for 10 years). Re-run it to regenerate them.

* Key Store (`nifi_mongo/mongo_user/mongo_user.p12`) Password: `mongodemostorepass`
* Trust Store (`nifi_mongo/truststore.p12`) Password: `mongodemostorepass`

MongoDB is pinned to 7.0 because 8.x and 9.x refuse to start on Linux kernels 6.19 and newer.

## Mongo ReplicaSet w/ SSL

To set up this demo, do the following:

1. `docker-compose -f docker-compose-mongo-ssl.yml up`
2. `docker exec -it mongo1 mongosh --tls --tlsCertificateKeyFile /opt/mongo/mongo_user/combined.pem --tlsCAFile /opt/mongo/nifi-cert.pem mongo1:27017`
3. Run the statement listed below:

```
rs.initiate(
  {
    _id : "myrs",
    members: [
      { _id : 0, host : "mongo1:27017" },
      { _id : 1, host : "mongo2:27017" }
    ]
  }
);
```

## MongoDB Sharded Collection with SSL

Docker Compose configuration file: `docker-compose-mongo-ssl-shard.yml`

Bring up the Docker Compose file and wait until all containers are running (could take up to 2 minutes).

Connect to the MongoDB configuration server using this command:

`docker exec -it mongocfg mongosh --tls --tlsCertificateKeyFile /opt/mongo/mongo_user/combined.pem --tlsCAFile /opt/mongo/nifi-cert.pem mongocfg:27019`

Once the shell is up, run this configuration:

```
rs.initiate(
  {
    _id: "myrs",
    configsvr: true,
    members: [
      { _id : 0, host : "mongocfg:27019" }
    ]
  }
);
```

Now, connect to mongo1 with this command:

`docker exec -it mongo1 mongosh --tls --tlsCertificateKeyFile /opt/mongo/mongo_user/combined.pem --tlsCAFile /opt/mongo/nifi-cert.pem mongo1:27018`

Run this configuration:

```
rs.initiate(
  {
    _id : "myrs_int",
    members: [
      { _id : 0, host : "mongo1:27018" },
      { _id : 1, host : "mongo2:27018" }
    ]
  }
);
```

At this point, both replica sets should be updated. Connect to the mongos service using this command:

`docker exec -it mongos mongosh --tls --tlsCertificateKeyFile /opt/mongo/mongo_user/combined.pem --tlsCAFile /opt/mongo/nifi-cert.pem mongos:27017`

Run this command to make `mongos` aware of the replica set (one member is enough, the rest are discovered):

```
sh.addShard("myrs_int/mongo1:27018")
```

Now, set up a test database like this:

```
sh.enableSharding("mystuff")
sh.shardCollection("mystuff.test", { msg: 1 });
```

You should now be able to insert a document like this into `mystuff.test`:

```
use mystuff

db.test.insertOne({ msg: "Hello, world" });
db.test.insertOne({ msg: "Buongiorno, mondo!"});
```
